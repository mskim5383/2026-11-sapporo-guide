# R3 조판 기록 · 축소 인쇄 수정, 배율 게이트, 검수 r3 조판 항목 (아트 디렉터, 2026-11-08)

## TL;DR

- **R2 정식 빌드(72쪽)는 축소 인쇄였다.** Chrome 이 책 전체를 0.931배로 줄여 인쇄했다. 그래서 본문 9pt 가 8.39pt 로, 캡션 7.5pt 가 약 7pt 로 찍혔다.
  - 원인: 23 「밤마다 고르는 표」 O/X 칸에 준 `white-space: nowrap`(제 CSS). 긴 칸(「X 출장 행사, 일반 영업 없음」)이 줄을 못 바꿔 표가 판면보다 35px 넓어졌다. Chrome 은 판면보다 넓은 요소가 있으면 문서 전체를 쪽 폭에 맞춰 줄인다.
  - 고침: O/X 칸 줄바꿈 허용(`src/style.css`). 판면보다 넓은 요소는 이제 0개다(아래 게이트의 진단).
- **빌드 게이트를 넣었다**(`build/build.mjs`). 인쇄 배율이 1에서 0.5% 넘게 벗어나면 경고하고, 넓은 요소를 짚는다.
  - 방법 ①: 인쇄 패스에 10pt 표식을 심어 PDF 글자 크기를 잰다.
  - 방법 ②: 최종 PDF 본문 글자 크기의 최빈값이 9pt·9.5pt 인지 본다.
  - 결과는 `qa/build-report.json` `printScale`.
- **실제 크기 tmp 빌드(21:51 원고): 84쪽.** 원고 80쪽 + 끝 메모 3쪽 + 뒤표지. 원고가 1쪽 줄면 80쪽, 9쪽 줄면 72쪽이다.
- 검수 r3 조판 항목 중 #7·#9·#10·#11·#31 을 고쳤다. #8(특집 중간 빈자리)과 #12(러닝헤드)는 원고 몫이라 아래에 제안만 적었다.
- 원고 문장은 고치지 않았다. 정식 빌드는 하지 않았다(`dist/`·`qa/pages` 는 R2 그대로라 축소 인쇄본이다).

## 배율 게이트 (`build/build.mjs`)

| 검사 | 방법 | 경고 |
|---|---|---|
| 패스 표식 | 인쇄 패스 HTML 첫 원고에 흰 10pt 글자 `ZZS[10]ZZ` 를 심고 PDF 글자 크기를 잰다(`pdftext.mjs` 에 `size` 추가) | 0.995~1.005 밖이면 「인쇄 배율 0.931: … 넓은 요소: bars td.x +35px 「X 정기휴무」 …」. 넓은 요소는 판면 폭(457px) 인쇄 레이아웃에서 원고 오른쪽 끝을 넘는 가장 안쪽 요소(표지·뒤표지·SVG·스크롤 상자 안 제외) |
| 최종 본문 | 최종 PDF 2쪽~끝 앞 쪽의 글자 크기(글자 수 가중) 최빈값이 9pt 또는 9.5pt 에서 0.5% 안 | 「최종 PDF 본문 글자 크기 최빈값 8.39pt 가 기준 9·9.5pt 와 다릅니다」 |

- 검증: O/X `nowrap` 을 되살린 CSS 사본(`tmp/ad/style-nowrap.css`)으로 빌드하면 두 경고가 다 나고 원인 칸 5개를 짚는다(표식 0.931, 본문 8.39pt). 지금 CSS 는 표식 1.000, 본문 9pt.
- 나고야판(`qa/layout-log-r4.md`)과 같은 문제다. 이쪽은 위 두 방법을 쓴다. 코디네이터가 준 `fontsize.mjs` 와 같은 원리(글자 변환 행렬의 크기)다.
